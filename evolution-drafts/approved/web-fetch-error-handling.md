- **进化强度：** aggressive (100%)

## 问题分析

### 原始问题
在2026-04-28的日报生成任务中，web_fetch工具出现了严重的错误问题：
- 总工具调用：28次
- 错误次数：7次
- 错误率：25%
- 影响：任务执行效率低下，成功率降低

### 错误类型分析
基于观察，主要错误类型包括：
1. 网络连接超时
2. DNS解析失败
3. SSL证书错误
4. 连接被拒绝

## 解决方案

### 1. 错误分类处理规则
已添加到AGENTS.md的"Tools"部分：

**错误分类处理规则：**
1. **网络超时错误**：自动重试2次，每次间隔5秒
2. **DNS解析错误**：检查URL格式，自动添加http://前缀（如果缺失）
3. **连接拒绝错误**：等待30秒后重试1次
4. **SSL证书错误**：尝试使用http://替代https://（仅限非敏感信息）

### 2. 批量URL处理策略
- 当需要处理多个URL时，先测试第一个URL的连接性
- 如果第一个URL失败，暂停批量处理并报告
- 使用并行处理时限制并发数为3，避免网络拥塞

### 3. 错误日志记录
- 所有web_fetch错误必须记录到 `memory/YYYY-MM-DD.md` 中
- 记录：URL、错误类型、重试次数、最终状态
- 定期分析错误模式，优化URL选择策略

### 4. 备用数据源策略
- 对于关键信息，准备2-3个备用URL
- 主URL失败时自动切换到备用URL
- 不同数据源的结果进行交叉验证

### 5. 用户通知阈值
- 单次任务中web_fetch错误超过3次 → 通知用户
- 错误率超过20% → 暂停任务，请求用户确认
- 连续3天出现高错误率 → 建议检查网络配置
